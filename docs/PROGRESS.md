### Image export (Phase 6)

- `src/components/export/export-map-svg.tsx` is a pure inline SVG export layout:
  1600 × 1000 landscape, system fonts only, all 195 country paths, count,
  percentage, progress bar, optional title, brand mark, year, and footer. It has
  no external images, fonts, or links, so canvas is not tainted.
- `src/lib/export-map.ts` accepts only `{ visited, count, displayName?, year }`.
  It drops unknown/retired/duplicate codes, derives the count from the cleaned
  set, collapses whitespace, caps the title at 40 characters, and normalises the
  year.
- Delivery: rasterize at 2× with canvas to a 3200 × 2000 PNG. If
  `navigator.canShare({ files })` supports the file, open the native share sheet;
  otherwise download. A cancelled share does not force a download. If canvas
  fails, download the same inline SVG.
- `src/components/export/export-map-panel.tsx` renders on the personal map and on
  shared maps. It has a title field, a rose **Preview** toggle (the image is
  hidden until pressed, and stays mounted while hidden because export serializes
  it), a **Download** button (renamed from "Share or download image" on
  2026-10-28; it still opens the native share sheet where supported), and
  progress/status/error states. The on-screen
  privacy paragraph was removed (ADR-035); the guarantee still comes from the
  input type and tests. On a shared map it receives the combined country
  codes by default, or the selected member's codes (or the union of the checked
  members); member names, map names,
  emails, ids, per-member counts, notes, and visit dates are never passed to the
  renderer.
- The export is one landscape layout. There is no aspect-ratio picker, PDF,
  animated export, server-side render, custom theme, or region breakdown in the
  image.
- Tests cover input minimality/sanitisation, 0/2/all visited, 195 exported paths,
  no external assets, escaped title text, combined shared export, comparison-view
  export staying combined, selected-member export, and the absence of member
  names or the map name.

### Country dataset revision (2026-10-27)

- The canonical dataset is now exactly **195 recognized countries**: the 193 UN
  member states plus the Holy See (`VA`) and Palestine (`PS`). The scope excludes
  dependent territories, Kosovo (`XK`), Taiwan (`TW`), Western Sahara (`EH`),
  Antarctica (`AQ`), and all other non-state units.
- `scripts/generate-countries.mjs` filters `@svg-maps/world@2.0.0` through one
  canonical code list. It emits 195 metadata entries and 195 paths, rejects any
  other package version, and is deterministic. No Natural Earth or custom
  Antarctica geometry remains.
- Holy See's display name is **"Holy See (Vatican City)"** so both terms are
  searchable. `PS` and `IL` remain separate units.
- Five continent regions total 195: Africa 54, Americas 35, Asia 48, Europe 44,
  Oceania 14. The old Antarctica region and dependent-territory assignments are
  gone.
- Migration `20261027120000_limit_to_recognized_countries` deletes visits to
  retired codes. It was applied to the Neon development database and the local
  test database. The server read boundary also filters unknown codes.
- The public geometry asset is ~1.1 MB raw / ~377 KB compressed. Copyright
  attribution now names only `@svg-maps/world` (CC-BY-4.0).

- Every one of the 195 countries now carries a continent-level region from
  `src/data/country-regions.ts` (Africa, Americas, Asia, Europe, Oceania),
  attached by `src/data/countries.ts`. The grouping uses UN M49 at the continent
  level; transcontinental countries use their UN region. It is static code, not a
  table or migration.
- The personal country list stays deliberately simple after owner review: one
  search field and the alphabetical 195-row checklist. There are no
  visited/region/sort controls, reset action, or result count. A checked country
  name and its checkbox use dusty rose; there is no separate "visited"/"not
  visited" row text. The map legend and visual-aid note were removed.
- The personal progress card shows a continent breakdown with marked/total
  values and small CSS bars. Marked values sum to the headline visited count;
  no charting library was added. **By region** is a closed-by-default dropdown
  (`<details>`) on the personal map (ADR-035).
- The shared map adds a comparison derived from the already-authorized aggregate
  view: **Visited by everyone**, **Only you**, and **Not yet by anyone**. These
  are toggle buttons under **Show more → Compare progress** (pressing the active
  one returns to the combined view). A comparison updates the map, progress,
  region breakdown, list, title, empty state, and count. "Only you" and "not yet
  by anyone" disclose no field the per-member filter did not already send. No
  new server query or migration.
- Shared and personal lists are height-limited and scroll on mobile; shared
  comparison lists show region names and remain read-only.
- Pure helpers in `src/data/country-insights.ts` implement region counts and
  comparison sets; unit tests cover region sums, unknown codes, and all three
  comparison sets. The initial filter/sort helpers were removed with the
  controls.

### Shared maps (Phase 4)

- Signed-in pages: `/shared` lists the maps a user belongs to ("Maps you belong
  to:") and, below it, creates a new map ("Create a shared map:");
  `/shared/[mapId]` shows the combined view, member list, and owner
  controls; `/invite/[token]` previews and accepts an invitation. Non-members
  receive the app's 404 page for a map id.
- **`/shared/[mapId]` layout (ADR-035, revised 2026-10-28), top to bottom:** map
  name/description; a summary card (countries in the current view as "X of 195",
  member count, percentage, progress bar) with a closed **Show more** dropdown;
  the map card ("Shared map", no legend); "Countries in this view" (no privacy
  paragraph); the export panel; then one closed **Members and settings**
  dropdown (just **Members** for non-owners). **Show more** contains **Show**
  (checkboxes: All plus each member, all checked by default) and **Compare
  progress** (with the region breakdown). **Members and settings** contains the
  member list (Remove/Leave) and, for the owner only, **Invite someone**,
  **Pending invitations**, **Map details**, and the **Danger zone**. The page
  renders it on the server, so non-owners never receive invite controls or
  pending-invitation emails. Ticking a member returns from any comparison to the
  combined view; "All" always means the combined view, even on a one-member map.
- The signed-in header nav reads **Home** (was "Map"; still links to `/map`),
  **Shared**, **Account** with the current page marked. **On phones (below `sm`)
  the app is laid out like an installed app:** the top bar is the logo and an
  icon-only Sign out, and a fixed bottom tab bar holds Shared (left), Home
  (middle), Account (right) as icons with labels (`src/components/app/app-nav.tsx`).
  `viewport-fit=cover` and safe-area padding keep it clear of the home indicator.
- **Phone footer (2026-10-28).** Below `sm` the signed-in footer is hidden and
  the in-page "About the map data" attribution under the maps is hidden; the
  Account page has a phone-only **About** section (Privacy, Made by, the
  attribution, ©). Desktop is unchanged. The Preview/Download buttons are
  equal-width and side by side on phones. The map cards on `/shared` alternate green and pink
  (green, pink, green… in one column; a green/pink checkerboard in two columns),
  via `src/lib/card-tones.ts`.
- The shared-map tables already existed from the Phase 2 migration. Phase 4 uses
  them as-is: **no new migration or schema change** was needed.
- Creating a map inserts the map and the owner's `OWNER` membership in one
  transaction. Any signed-in user can create a map; creating maps is not
  limited beyond the existing auth rate limits.
- Owner actions: rename/update description, invite by email, revoke pending
  invitations, remove members, and delete the map after typing `DELETE`.
  Members can leave; the owner cannot leave and must delete instead. Removing a
  member or leaving deletes only the membership, never the person's private
  visits.
- Invitations use 32 random bytes (43-character base64url), stored as SHA-256
  hex. They expire after 7 days, are single-use, and are revocable. Acceptance is
  an atomic conditional update followed by membership creation. Re-inviting the
  same email revokes the previous pending link in the same transaction.
- Invitation preview and acceptance require the signed-in account email to match
  the invited address. Invalid, expired, revoked, used, and malformed tokens get
  a generic unavailable state; a different signed-in email gets a distinct
  message but never sees the map name. Pending invitation emails are only
  queried for the owner.
- Invitation email is best-effort via Brevo and contains only the map name and
  link. The owner can always copy the link from the UI if delivery is skipped or
  fails. The raw token is never logged by application code.
- The combined view is computed server-side from an authorization-scoped query.
  The client receives each member's display name, membership id, and deduplicated
  country-code set (needed for the filter), plus combined country counts. It does
  not receive emails, user ids, raw visit rows, notes, or visit dates.
- Shared maps are read-only for everyone, including the owner. The map surface
  has no checkboxes or toggles on countries; members change their own map from
  `/map`. The member checkboxes (in **Show more**) choose whose marks are
  combined, and the counts/list follow them.
- `/shared` and `/shared/[mapId]` are optimistically protected by `proxy.ts` and
  re-checked with `requireSession()` / `requireMapAccess()` on the server.
  `/invite/[token]` is public so a signed-out recipient can sign in or create an
  account; the raw token is shown only in the URL path.
- `safeNextPath` restricts post-auth redirects to same-origin paths. Sign-in and
  sign-up preserve an invitation `next` parameter; the invite page uses a
  no-referrer metadata tag and response headers (plus noindex and no-store).
- Shared navigation, account/home/footer copy, read-only map CSS, and the
  create-map/invite/settings/delete/revoke/remove/leave forms are implemented.
  The signed-in header and the auth pages use the logo mark; the signed-in
  footer matches the public footer.

### Country dataset and personal map (Phase 3)

- The current canonical dataset is the revised 195 recognized countries described
  above. It was originally built as 250 units on 2026-10-26 and converted on
  2026-10-27. Palestine (`PS`) and Israel (`IL`) are separate units. Generated
  codes/names are in `src/data/countries.generated.ts`; the hand-authored
  continent assignment is in `src/data/country-regions.ts`; geometry is in
  `public/map/countries.json`.
- `scripts/generate-countries.mjs` filters the source to the canonical 195,
  normalizes names, sorts codes, asserts the count, creates output directories,
  and requires exactly `@svg-maps/world` `2.0.0`. `npm run data:countries`
  reproduces both outputs deterministically.
- `/map` is a signed-in, user-scoped page: a 195-path SVG map, searchable
  195-row country list, count/progress bar, continent stats, export panel, empty
  state, geometry loading/error/retry, route error boundary, and source/licence
  disclosure.
- Map geometry is fetched after first paint from `/map/countries.json`, validated
  against all 195 codes, and is not bundled into JavaScript. Raw asset size is
  ~1.1 MB; local production compression measured ~377 KB. It is public data.
- Visits are stored in `visited_countries` with a unique `(userId, countryCode)`
  constraint. `setVisitedCountryAction` rejects unauthenticated callers and
  codes outside the dataset; reads/writes are scoped to the session user.
- The client updates optimistically and rolls back with an error message when
  the Server Action fails. Counts are server-rendered initially.
- Narrow screens show the map first, with the country list below. From `lg`
  upward the map and list are side by side. The map can be zoomed and panned
  (2026-10-28): Reset / − / + buttons, pinch, Ctrl/⌘ + scroll, and drag once
  zoomed, up to 8×, on both the personal and shared maps (`zoomable-map.tsx`,
  `src/lib/map-zoom.ts`). A drag never marks a country; a tap does. Zoom is
  view-only (not saved, not in the export). At
  320/390 px there is no horizontal overflow; this was fixed after finding an
  intrinsic grid width of 463 px (`grid-cols-1` + `min-w-0`).
- Four client auth forms now use `method="post"` so a failed JavaScript boot
  cannot put a password into the URL.
- User-facing copy describes the product only. Internal phase numbers and
  future-feature timing were removed from the landing page, app footer, and
  account page; `README.md` still records project status for contributors.

### Accounts and authentication (Phase 2)

- Better Auth 1.7.12 with email/password, database sessions, and the Prisma
  adapter; handler at `/api/auth/[...all]`.
- Password policy: 12–128 characters, hashed by Better Auth (scrypt). Password
  reset links expire after one hour, are single-use, and revoke sessions.
- Sessions: 30-day lifetime, one-day rolling update, no cookie cache. Cookie
  observed locally as `HttpOnly`, `SameSite=Lax`, `Path=/`, 30-day `Max-Age`.
  `Secure` is applied by Better Auth in an HTTPS production origin; it could not
  be observed over local HTTP.
- Pages: `/sign-in`, `/sign-up`, `/forgot-password`, `/reset-password`, and
  `/account` with name, password, and account-deletion forms.
- Password changes revoke every session (including the current one) and redirect
  to sign-in with a success notice. This avoids a session-rotation race in the
  client router.
- Account deletion is password-gated, enabled in Better Auth, and relies on
  Prisma cascades. The UI warns that owned shared maps are deleted.
- Welcome email is sent once, **after the address is verified** (it used to be
  attempted at sign-up), and tracked with `welcomeEmailSentAt`; a missing
  `BREVO_API_KEY` makes it a logged no-op, and send failures never block
  verification.
- **Email verification by 6-digit code (Phase 8, ADR-036, 2026-10-28).** Sign-up
  creates an unverified account with no session and emails a code (valid 10
  minutes, 5 attempts, single use, stored hashed). The sign-up form then shows a
  "Check your email" step (`VerifyEmailForm`); a correct code verifies the
  address and signs the person in. "Send a new code" has a 60-second cooldown.
  Signing in to an unverified account (after the correct password) emails a new
  code and shows the same step; wrong passwords still get the generic message. A
  new sign-up for an address that only has an unverified account replaces it (no
  squatting). The plugin's passwordless sign-in and reset-by-code are disabled.
  In development, if mail cannot be sent, the code is printed to the server
  console (never in production). The two existing accounts were marked verified
  once with a one-off SQL update.
- Rate limits are enabled only in production (Better Auth, per-instance memory):
  sign-in 10/15 min, sign-up 5/hour, reset request 3/hour, reset submit 10/15 min.
- Server-side authorization gate `requireSession()`; the proxy only redirects
  `/account` when no session cookie is present. Fake/expired cookies still hit
  the server check.
- CSRF origin checks are enabled by Better Auth; cross-origin auth POSTs return
  403. Sign-in failures are generic and identical for unknown emails.
- Local development uses Homebrew PostgreSQL 18 (`atlasshare_dev`,
  `atlasshare_test`). The runtime adapter is Neon for `*.neon.tech` hosts and
  `@prisma/adapter-pg` otherwise.

## 4. Decisions carried from Phase 2

Full records in `DECISIONS.md` (ADR-017 onwards).

- Local PostgreSQL 18 for development/testing; Neon remains the production
  target. Runtime adapter is selected from the database host.
- Lazy environment validation and lazy auth/database singletons so `next build`
  needs no secrets.
- Email/password minimum 12, maximum 128; no email-verification enforcement yet.
- 30-day database sessions, 1-day rolling refresh, no session cookie cache.
- Production-only, in-memory rate limits; accepted as a speed bump on serverless.
- Welcome email best-effort with a once-only claim; missing Brevo config is a
  logged skip.
- Password change signs out every device and requires signing in again.
- Account deletion is immediate after password confirmation and relies on
  cascades.
- Proxy only performs optimistic cookie checks for `/account` and `/shared`;
  auth pages are not redirected by cookie presence (avoids rotation races and
  lets a signed-in user reach sign-in).
- Better Auth password-reset tokens are stored raw in `verification.identifier`
  by the library. Accepted for now (single-use, ≤1 hour) and recorded as a
  limitation; invitation tokens remain hashed by design.

### Phase 3 decisions

Full records in ADR-024, ADR-032, and §5. ADR-025 recorded the original
250-unit/Antarctica source and is superseded by ADR-032.

- Use the curated `@svg-maps/world@2.0.0` dataset filtered to 195 recognized

- Auth forms submit with `method="post"`; this is a hardening fix, not a new auth

### Phase 6 decisions

Full records in ADR-011 (original approach), ADR-033 (implementation), and
ADR-034 (shared-map scope revision).

- One 1600 × 1000 landscape export rendered at 2× (3200 × 2000). No
  aspect-ratio picker, PDF, animation, or server-side rendering.

  download if canvas fails. A cancelled share does not force a download.
- No external fonts/images; system font stacks and inline paths only.

Full records in ADR-029, ADR-030, and ADR-031.

- Region is static dataset metadata, not a database table: UN M49 continent-level
  grouping in `src/data/country-regions.ts`, attached to the canonical country

  Armenia, Azerbaijan, Georgia, and Kazakhstan are Asia. After ADR-032, the five

  no visited/region/sort controls. Checked names and checkboxes use rose; the

  "Only you" uses count-one countries in the current member's set; "not yet by
  anyone" uses the dataset minus the combined union.

  conflating it with the "visited by everyone" overlap set. (ADR-035 moved the
  comparison and member checkboxes into the **Show more** dropdown.)

### Phase 4 decisions

Full records in ADR-012, ADR-013, and ADR-026.

- Shared maps are explicit-membership only: no public links, anonymous viewing,
  or “anyone with the link” access.
- All members see each other's display names and country-level marks for the
  filter; the client receives membership ids and deduplicated country-code sets,
  never emails, user ids, raw visit rows, notes, or dates. Pending invitation
  emails are owner-only.
- Owner and member roles only. The owner manages details, invitations, members,
  and deletion; members can leave. The owner cannot leave.
- The shared map is read-only for everyone; personal visits are changed only on
  `/map`. Removing a member or leaving never deletes private visits.
- Invitations are 7-day, single-use, per-email, hashed at rest, revocable, and
  re-inviting replaces the prior pending link. Email delivery is best-effort;
  the owner can always copy the link.
- Destructive map deletion requires typing `DELETE`; member removal/leave are
  confirmations but do not delete personal data.
- Post-auth redirects use `safeNextPath`; only same-origin paths are accepted.
- The shared-map tables already existed, so Phase 4 added no migration. New
  routes/actions reuse the existing schema and indexes.
- Invitation acceptance is not rate-limited. Token entropy is 256 bits and a
  valid link still requires the matching signed-in email, but a forwarded link
  can be redeemed by whoever can register the unverified invited address first.
  This is recorded as an accepted risk, not claimed as solved.

## 9. Known limitations and debt

- **Map visual review is delegated.** Layout was checked with Chrome metrics at
  320/390/1200/1280 px and screenshots were captured, but the agent did not
  visually approve the rendered map. Physical-phone touch, Safari/Firefox,
  keyboard-only navigation, screen-reader output, geometry error/retry, offline,
  and throttled-mobile performance remain unverified.
- **Export cross-browser and physical-share QA are incomplete.** The native share
  payload, PNG download, and SVG fallback were exercised in headless Chrome, but
  no physical iOS/Android device, Safari, or Firefox run has confirmed the share
  sheet, attachment opening, font metrics, or canvas limits.
- **The export is one fixed landscape layout.** It is 3200 × 2000, with an
  optional 40-character title; there is no aspect-ratio picker, custom theme,
  PDF, animation, or region breakdown. A shared-map export intentionally contains
  the combined marks of all members by default (or the selected member's marks),
  but never member identities; sharing the image can reveal the group's combined
  travel footprint.
- **Region grouping is a travel-map convention, not a political statement.**
  It follows UN M49 continents, so Cyprus, Türkiye, Armenia, Azerbaijan, Georgia,
  and Kazakhstan count as Asia and Russia counts as Europe. Region labels are
  English-only; a user expecting a different convention may disagree at the
  edges. The 195-country scope excludes territories and several contested or
  non-recognised units; that is a product decision, not a boundary claim.
- **Search state is not in the URL.** It resets on reload and there is no saved
  search preference. Filter/sort controls were removed after owner review.
- **Shared comparison is derived from the loaded aggregate.** It is not real-time
  and does not re-query on a timer; opening or refreshing the page picks up new
  visits. "Visited by everyone" naturally becomes empty as members join.
- **No charting library.** Region bars are CSS. The image export includes the
  count, percentage, and map, but not the region breakdown; there is no CSV
  export.
- **Authenticated pages were not Lighthouse-audited in Phase 6.** The earlier
  100/100/100 result applies only to the public landing and invitation pages.
- **Geometry is a public 1.1 MB asset.** Local production compresses it to
  ~377 KB; it is ETag-revalidated (`max-age=0`) at an unversioned path. A CDN
  should use a short TTL or a versioned URL if long caching is desired. It never
  contains visit data.
- **The 195-country map has no Antarctica outline and no dependent territories.**
  This is deliberate after ADR-032; do not reintroduce a "countries & territories"
  toggle without a new product decision, migration review, and copy update.
- **Map zoom is pointer/touch-driven.** The +/−/Reset buttons are keyboard
  accessible, but panning is drag-only (no arrow-key panning) and plain scroll
  does not zoom, by design, so the page can still scroll. Pinch and touch drag
  have not been tried on a physical phone. The map remains a visual shortcut; the
  country list is the non-visual path.
- **Shared maps are read-only and not real-time.** Members update their own map
  on `/map`; the shared page reflects accepted membership and country changes on
  the next request/revalidation. There is no live presence, comments, or owner
  transfer.
- **Member names are visible to all members of a map**, by design, so the filter
  can identify people. Emails, user ids, raw visit rows, notes, and visit dates
  are not sent to the shared view. Pending invitation emails are owner-only.
- **Invitation tokens are in the URL path.** Application code does not log them,
  and invite responses send `Referrer-Policy: no-referrer`, `X-Robots-Tag`, and
  `Cache-Control: private, no-store`. Hosting/proxy access logs can still record
  the path, so production log retention and access must be restricted.
- **Invitation acceptance and invitation creation are not rate-limited.**
  Acceptance tokens have 256 bits of entropy; guessing is infeasible. A forwarded
  link can satisfy the email check by registering the unverified invited address
  first (see the email-verification limitation).
- **Email delivery is verified through Brevo**, but visual rendering and the
  password-reset message through the app still need a human check. The welcome
  and invitation messages are not retried if email is disabled or fails.
- **Invitation email delivery is best-effort**; the owner can copy the link. No
  resend, delivery webhook, bounce suppression, or retry queue is implemented.
- **The `note` and `firstVisitedAt` columns are unused** by the approved initial
  scope (D2). They remain reserved; remove them with a migration before launch if
  notes/dates are still unwanted.
- **Brevo IP allowlisting is a deployment concern.** Local calls required
  authorizing the current egress IP. Vercel's outbound IPs are dynamic, so
  production will need IP blocking disabled, static egress, or a scoped M2M token.
- **Brevo adds a `List-Unsubscribe` header** to transactional mail; Gmail may show
  its own unsubscribe control. The free plan cannot remove it. Domain
  authentication is the main deliverability fix.
- **Password-reset tokens are stored raw** by Better Auth in
  `verification.identifier` (the identifier includes the token). They are
  single-use and expire in one hour. Replacing this needs a custom reset flow.
- **Auth rate limiting is per-instance memory** and only active in production.
  It slows basic brute force on sign-in/sign-up/reset but is not a shared limiter
  and does not cover shared-map Server Actions.
- **No MFA or OAuth.** Email verification is now enforced (ADR-036), so
  invitations rest on a verified address. Remaining email-code caveats: anyone
  can request a code for any address (nuisance email, rate-limited only per
  instance in production), and signing up with an already-verified address shows
  the code screen but sends nothing.
- **Sign-up depends on email delivery.** If the code never arrives, the person
  can request a new one, but if Brevo is blocked (for example by IP) nobody can
  finish signing up in production. Development prints the code to the server
  console in that case. Test delivery from a fresh address before launch.
- **Secure cookies are not observable locally** because the smoke test used
  HTTP. Production uses an HTTPS origin.
- **No CI, deployment, or error monitoring.** Checks run locally.
- **npm audit** reports 8 advisories (1 critical) through development tooling:
  `@better-auth/cli` carries its own older Better Auth, drizzle-orm, and lodash;
  Prisma Studio pulls lodash. The runtime uses Better Auth 1.7.12, which is
  outside the affected range, and none of these are in the production bundle.
  Re-check before deployment and replace/upgrade when fixes are available.
- **Never-verified accounts are never purged.** A sign-up that is never completed
  stays in the database (name, address, password hash) until someone signs up
  again with the same address, which replaces it. The privacy page says so. Add a
  scheduled cleanup (for example, delete unverified accounts older than 7 days)
  before launch; it is safe because unverified accounts hold no data.
- **The privacy page has no contact route.** The "Questions" section (which linked
  to a non-working issue tracker) was removed on 2026-10-28. Deletion is
  self-service on Account, but a person with a privacy question has no listed
  address. Add a contact email or a working tracker before launch.
- **The OG/Twitter link-preview images still draw the old "A" mark** rather than
  the new logo, and `og:url` shows localhost unless `NEXT_PUBLIC_APP_URL` is set.
- **Local origin must match the dev port.** If port 3000 is taken (it was, by
  another app on this machine), Next starts on 3001 and `.env` must be updated to
  that origin or sign-up/sign-in fail with "Invalid origin". `.env` is
  gitignored; `.env.example` stays on 3000.
- **The export privacy reassurance text was removed from the UI** at the owner's
  request (ADR-035). The image content is unchanged and test-enforced.
